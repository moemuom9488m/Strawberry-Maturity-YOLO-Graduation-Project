## 🎯 訓練策略
為了提升自走車在農田實際巡視時的辨識率，特別針對「光線變化」、「自走車晃動」以及「草莓互相遮擋」設計了**二階段微調策略**：

1.  **一階段基礎訓練 (Stage-1)**：
    使用較輕量的增強，讓模型先學會基本特徵，達到收斂狀態。
2.  **二階段困難樣本強化 (Stage-2 Fine-tuning)**：
    *   **特徵保護**: 設定 `freeze=10`，鎖住前 10 層 Backbone 不更新，保護一階段學到的基礎特徵。
    *   **學習率微調**: 降低學習率至 `lr0=0.0001`，進行微小權重修正。
    *   **高強度幾何增強 (抗晃動)**: 開啟 `degrees=15.0` (旋轉), `translate=0.2` (平移), `shear=2.0` (剪切)，模擬自走車行進時的顛簸視角。
    *   **高強度混入增強 (抗遮擋與解決類別不平衡)**: 
        *   使用 `mosaic=1.0` (4 圖拼接) 稀釋純背景。
        *   使用 `mixup=0.15` (半透明疊加) 與 `copy_paste=0.1` (複製貼上目標) 物理性增加稀有目標的出現頻率。
        *   開啟 `multi_scale=True` 強制模型適應不同距離的草莓尺寸。

## ⚠️ 遇到問題
在從 YOLOv8/v10 轉移至最新 YOLO11 架構，並嘗試設定二階段訓練參數時，遭遇了以下嚴重報錯導致 Kernel 崩潰：

1.  **參數相容性失效 (`SyntaxError`)**：
    嘗試加入 `focal_loss=True` 或 `fl_gamma=1.5` 來手動解決背景佔比過高的問題時，系統報出 `'focal_loss' is not a valid YOLO argument`。
2.  **Jupyter 環境變數污染**：
    報錯訊息中出現了奇怪的 JSON 路徑：`Arguments received: ['yolo', '--f=...kernel-xxx.json']`，顯示模型把 Jupyter 的底層啟動參數當成了訓練參數。
3.  **潛在的 OOM (Out Of Memory) 危機**：
    在開啟 `multi_scale=True` 的情況下，頻繁重新執行二階段訓練儲存格，導致顯存不斷堆積未釋放。

---

## 💡 解決方式

1.  **擁抱現代架構，棄用舊版參數**：
    查閱文檔後確認，最新的 YOLO 架構 (8.4+) 已全面移除手動設定 Focal Loss。模型改為依賴底層的 **Task-Aligned Assigner** 與 **Distribution Focal Loss (DFL)** 來自動解決正負樣本不平衡。因此，我們在代碼中**徹底刪除了 `fl_gamma` 等參數**，並依賴前述的 `mosaic` 與 `mixup` 等物理增強方式來補強困難樣本。
2.  **加入環境隔離機制**：
    在訓練儲存格的最頂端加入 `sys.argv = [sys.argv[0]]`。這行指令能強制截斷並清空 Jupyter 的外部變數干擾，確保 YOLO 引擎只讀取到乾淨的訓練指令。
3.  **加入顯存安全閥**：
    在啟動 `model.train()` 之前，加入了強制的資源回收邏輯：
    ```python
    if 'model_stage2' in globals(): del model_stage2
    import gc; gc.collect()
    torch.cuda.empty_cache()
    ```
    確保不管重跑幾次，都不會因為舊模型殘留而吃光 16GB 的顯存。
4.  **建立防呆變數自癒**：
    使用 `try...except NameError` 包裹 `DATA_YAML_PATH` 等關鍵變數，確保單獨執行該儲存格時也能自動補齊變數，不必每次都從頭執行整個 Notebook。

2.  **資訊過載 (Verbose Log)**：YOLO 預設的訓練輸出過於頻繁，淹沒了重要的進度資訊。

### 💡 解決方式
1.  **禁用法**：將 `multi_scale` 設定為 `False`。二階段微調專注於 640 解析度精修即可。
2.  **靜音開關**：
    *   在訓練參數中設定 `verbose=False`（隱藏 Batch 細節）與 `plots=False`（不產生中間圖表）。
    *   引入 `logging` 庫並將 `ultralytics` 的 Log 等級設為 `WARNING`，徹底過濾冗餘系統訊息。

## 📅 時間
**2026年4月22日 12:55 (第 3 次維護)**

### 🏗️ 目前的模型架構
*   **自定義架構**: **YOLO11-Strawberry-P2-CBAM**
*   **核心組件**: 
    *   **P2 層**: 引入 160x160 高解析度特徵頭，強化對極小草莓的偵測。
    *   **CBAM (Convolutional Block Attention Module)**: 在偵測頭前注入通道與空間注意力，過濾背景雜訊。

### 🎯 訓練策略
*   **架構與權重分離**: 實作 `YOLO(cfg).load(weights)` 模式，確保自定義架構能正確加載 S 版預訓練權重。
*   **模組化封裝**: 將 CBAM 實作與 Ultralytics 註冊邏輯移至 `agent_tools/yolo_utils.py`，提升代碼可維護性。

### ⚠️ 遇到問題
1.  **YAML 角色混淆 (`RuntimeError`)**: 在一階段訓練中，誤將「模型架構檔 (.yaml)」當成「資料集設定檔 (data.yaml)」傳入，導致 `train: key missing` 報錯。
2.  **未知層報測 (`AttributeError`)**: 由於 YOLO 框架原生不包含 CBAM，直接讀取 YAML 會導致解析失敗。

### 💡 解決方式
1.  **修正路徑邏輯**: 明確區分 `MODEL_CFG` (架構) 與 `DATA_YAML_PATH` (資料)，並修正一階段訓練儲存格的參數傳遞。
2.  **動態注入模組**: 
    *   在 `agent_tools/yolo_utils.py` 中實作 CBAM 類別。
    *   使用 `setattr(modules, 'CBAM', CBAM)` 將模組動態注入 `ultralytics` 命名空間，使其能成功解析自定義 YAML。
3.  **代碼瘦身**: 透過 `from agent_tools import ...` 簡化 Notebook 內容，維持工作環境整潔。

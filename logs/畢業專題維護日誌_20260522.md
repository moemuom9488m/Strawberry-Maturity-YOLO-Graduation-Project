📅 **時間**: 2026年5月22日 13:38
🏗️ **目前的模型架構**: YOLOv11 雙側即時偵測與動態投影 / Gradio 後端穩定性優化
🎯 **訓練策略**: 重構後端核心邏輯，消除資源鎖定、記憶體洩漏與執行緒阻塞引起的 Web 伺服器崩潰當機。
⚠️ **遇到問題**: 
1. 使用者在影片推理執行過程中或多次重複啟動時，Gradio 應用會突然中斷連線或卡死當掉（出現 `ConnectionResetError` 與 `ProactorBasePipeTransport` 連線中斷異常）。
2. 原因分析：`YOLO` 推理和 OpenCV 影片寫入會長時間佔用 GIL 且阻塞 asyncio 事件循環；另外，暫存影片 `temp_output.mp4` 與 CSV 檔名固定，導致多人使用或重複點擊時發生檔案寫入衝突與死鎖；最後，YOLO 模型重複實例化卻未釋放，造成顯存逐漸溢出。
3. 若使用者上傳格式錯誤或缺少特定欄位的 CSV 資料，點雲繪製函數與統計計算會拋出 `KeyError` 等未捕獲異常，直接導致服務端無預警當機。

💡 **解決方式**:
1. **多用戶檔案隔離**: 改用隨機 `uuid` 作為暫存影片與 CSV 報告的檔名，杜絕磁碟讀寫鎖定衝突。
2. **強健性異常保護**: 採用 `try...finally` 結構，不論影片推理中途成功或失敗，皆能強制 release OpenCV `VideoCapture` 與 `VideoWriter`，避免資源被長期鎖定。同時對逐影格偵測與處理添加內層 `try...except`，避免單一壞影格中斷整個流程。
3. **防 CPU/GPU 執行緒阻塞**: 在動態 yield 前端畫面的 loop 中添加 `time.sleep(0.01)` 微小調度延遲，讓出 GIL 以使事件循環（event loop）的心跳封包得以及時回應，徹底杜絕 socket 連線逾時斷開問題。
4. **顯存與記憶體自癒**: 在推論前後手動觸發垃圾回收 `gc.collect()` 與 `torch.cuda.empty_cache()`，並在推論後 `del model`，完全消除顯存洩漏風險。
5. **CSV 載入安全防護**: 針對數位孿生 CSV 上傳新增大小寫不敏感之欄位對齊，並針對缺失欄位補齊合理預設值與容錯防禦，保證資料異常時亦能平穩運作，不引發主程式報錯當機。

📅 **時間**: 2026年5月22日 13:46
🏗️ **目前的模型架構**: YOLOv11 雙側即時偵測與動態投影 / Gradio 行動端網頁響應式優化
🎯 **訓練策略**: 針對行動端（手機/平板）網頁環境進行 RWD 佈局、觸控手勢防劫持與 WebGL 渲染效能調優。
⚠️ **遇到問題**: 
1. **行動端滾動劫持 (Scroll Hijacking)**：Plotly 圖表（2D 地圖、KDE 熱力圖與 CCPP 尋路軌跡圖）在手機瀏覽器上會攔截所有的拖拽與滑動手勢，導致使用者觸碰圖表區域時網頁「卡死」無法上下捲動。
2. **WebGL 性能開銷**：3D 立體數位孿生地圖高度為 500px，在小螢幕上完全霸佔整個版面，且行動端 GPU 渲染多個高密度網格時易導致瀏覽器發熱卡頓。
3. **Tab 選單折行跑版**：Gradio 的 `Tabs` 選單在手機窄螢幕上會因為寬度不足而強行折行，破壞現代 UI 美感。
4. **指標看板樣式干擾**：統計數據指標面板使用了 HTML 的行內 CSS 設定 `grid-template-columns: repeat(4, 1fr);`，這會覆蓋 RWD class 中的 CSS 規則，導致手機上卡片依然排成四列，產生極度嚴重的寬度擠壓與折行跑版。

💡 **解決方式**:
1. **防滾動劫持**：將所有 2D 展示型 Plotly 圖表（2D 動態地圖、CCPP 軌跡圖、KDE 熱力圖）的 `dragmode` 屬性一律設為 `False`，徹底停用拖拽交互，使觸控滑動手勢能直接穿透圖表傳遞給網頁，恢復平滑的頁面捲動體驗。
2. **Plotly 高度調降**：將 2D 圖表高度統一由 600px/550px 降至 450px，並將 3D 孿生圖高度由 500px 降至 420px，在圖表兩側與下方留出充足的「手勢安全區域」，方便手機用戶抓取空白處滑動網頁。
3. **Tab 導航橫向滑動**：在 CSS 中為 `.tab-nav` 注入 `display: flex !important; flex-wrap: nowrap !important; overflow-x: auto !important; -webkit-overflow-scrolling: touch !important;` 屬性，當螢幕寬度不足時，Tab 選單將自動轉換為精美的橫向可滾動標籤列，避免折行跑版。
4. **CSS 自適應 Grid 卡片**：清除 HTML 程式碼中 `summary_html` 根容器的行內 `grid` 樣式，統一移至外置 `custom_css` 的 `.stats-grid-container` class。並新增 `@media (max-width: 992px)` 媒體查詢，實現：PC 顯示四列、平板顯示兩列、手機顯示單列的自適應完美流暢版面。

📅 **時間**: 2026年5月22日 13:52
🏗️ **目前的模型架構**: YOLOv11 雙側即時偵測與動態投影 / Gradio 影片推理快取繪圖機制
🎯 **訓練策略**: 實作跳影格的框快取與 OpenCV 補繪機制，以消除加速推理時的閃爍（flickering）現象。
⚠️ **遇到問題**: 
1. 用戶播放處理後的影片時，偵測框（bounding boxes）會出現一閃一閃的閃爍現象。
2. 原因分析：為提升推理速度，系統使用 `step_interval = 3`（每 3 影格進行一次 YOLO 推理）。在跳過的非推論影格中，由於直接輸出原始影像，未繪製偵測框，導致影片播放時畫面在「有偵測框」與「無偵測框」之間交替閃爍，影響視覺流暢度。

💡 **解決方式**:
1. **設計影格偵測框快取**：在 YOLO 推理影格中，在 `for box in boxes:` 迴圈結束後，將當前影格偵測到的框資訊 `[xyxy, track_id, cls_name, conf]` 快取至 `last_boxes_to_draw`。並在每次執行 YOLO 推理前將該快取清空。
2. **非推論影格 OpenCV 補繪**：在跳過推論的影格中（`frame_idx % step_interval != 0`），讀取 `last_boxes_to_draw` 中的快取框，依據成熟度標籤動態匹配對應的 BGR 顏色（Level 1 藍綠色, Level 2 橘黃色, Level 3 紅橙色），使用 OpenCV `cv2.rectangle` 與 `cv2.putText` 手動將偵測框與置信度/ID 繪製在當前影格上。
3. **兼顧速度與視覺流暢度**：此設計保留了 3 倍的推理加速，同時讓偵測框在跳過的影格中持續平滑顯示，成功消除了閃爍現象。
